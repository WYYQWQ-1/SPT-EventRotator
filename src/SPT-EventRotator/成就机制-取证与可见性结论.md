# 任务线成就：机制取证 / 可见性结论 / 自检

> 2026-10-30 23:3x 独立复核。实现文件是 `AchievementInject.cs` + `achievements\*.json` +
> `images\achievement\*.png` + `LocaleInject.cs` 的 18 条文案（见 `成就注入-说明.md`）。
> 这份文档只回答三件事：**客户端凭什么认「完成任务线」**、**能不能按活动门控显隐**、**真跑的自检输出**。
> 全部结论来自本机 DLL 反编译 + 真数据/真 DLL 进程内实测，未启动游戏、未部署。

## 1. 客户端凭什么认「这些任务全做完」

判别字段是 **`conditionType`**（不是 `type`）。证据链（`EscapeFromTarkov_Data\Managed\Assembly-CSharp.dll`）：

1. `EFT.EftJsonConverters..cctor` 建了一张 **54 个 JsonConverter** 的表，第 11 个是
   `PolymorphicConverter<ConditionSerializer, Condition, String>`，第 14 个是
   `JsonConverterAdapter<ConditionsDict, QuestConditionsListSerialized>`
   ⇒ 成就/任务的 `conditions{}` 全走这两个转换器。
2. `PolymorphicConverter.ReadJson`：先把整段条件 JSON 灌进 `ConditionSerializer`
   （`[JsonExtensionData] _newProps` 收全部字段），再 `ConditionSerializer.Deserialize`
   → `_parent = _props.Value<string>("conditionType")` → `KeyToType("Condition" + key)`
   在 `_types` 里按类名找。`_types` 里明确含 `typeof(ConditionQuest)`。
   ⇒ **缺 `conditionType` 会直接抛 `Unknown json condition type key`**（我实测过：
   官方 `achievements.json` 里那种只有 `"type": "Elimination"` 的写法，用客户端转换器裸解析会失败）。
3. `type` 是另一回事：它是 `ConditionCounterCreator` 的 `QuestTemplate.EQuestType` 字段
   （PickUp / Elimination / Completion …），所以才出现「成就条件里 `type: Elimination` 但没有 conditionType」的怪相
   —— 那是官方的计数器类条件，**不是**判别字段。
4. `EFT.Quests.ConditionQuest`：`target`（任务 id）+ `status`（`EQuestStatus[]`，`4` = Success）+
   `availableAfter`；`[OnDeserialized]` 里把 `value` 强制置 1。与 `quests.json` 里现成的前置任务条件**同形**：
   ```json
   {"availableAfter":0,"conditionType":"Quest","dispersion":0,"dynamicLocale":false,
    "globalQuestCounterId":"","id":"…","index":0,"parentId":"","status":[4],"target":"<任务id>",
    "visibilityConditions":[]}
   ```
5. 评估是**通用**的：`ConditionsConnectorsManager.InvokeConditionsConnector(TConditional conditional, …)`
   遇到 `ConditionQuest` 一律走 `ConnectConditionQuest(conditional, status, condition)`，
   内部 `_questBook.GetConditional(condition.target).QuestStatus ∈ condition.statuses` 就返回 1，否则 0。
   因为 `TConditional` 是泛型、`Achievement : Conditional<Achievement>`，**成就和任务共用同一条路**
   ⇒ 「任务线全部完成」= `availableForFinish` 里放 N 条 Quest 条件（AND）。

## 2. 服务端能不能运行期加成就

能，而且比任务更安全：

- `TemplateTable.Achievements` 就是 `List<Achievement>`（`SPT_Data\database\templates\achievements.json` 那个数组）；
  `AchievementController.GetAchievements()` 的 IL 逐字是 `Elements = templateTable.Achievements`
  ⇒ 追加即被 `/client/achievement/list` 拿走（每次进成就界面都会重新拉）。
- 先例：`PostDbLoadService.MergeCustomAchievements()` 就是「把 `CustomAchievements` 追加进 `Achievements`、按 id 去重」，
  但它跑在 PostDbLoad，时序不可控 ⇒ 我们直接追加 `Achievements`（`OnLoadOrder.Preload` = 100000）。
- `DatabaseIntegrityService.EnsureNoItemsAddedSinceProfilesLoaded()` 只比对 **`templateTable.Items` 的 key 快照**，
  加成就不会触发那个 abort。
- 文案键：`AchievementTemplate.Title => (Id + " name").Localized()`、`Description => (Id + " description").Localized()`
  ⇒ 键规则就是 `<成就id> name` / `<成就id> description`（与本体 53 条一致）。

## 3. 图标

- `ImageRouteImporter.OnLoadAsync` st Priority 100000（Preload）：把 `./SPT_Data/images/` **整棵树**注册成
  `/files/<相对路径去扩展名>`；`ImageRouter.CanHandle` 匹配时去扩展名 + 转小写
  ⇒ 成就写 `/files/achievement/ER_Xxx.png`，磁盘上放 `SPT_Data/images/achievement/ER_Xxx.png` 即可。
- 现实现是**启动时把 `<mod>/images/achievement/*.png` 复制进 `SPT_Data/images/achievement/`**
  （`TraderIconAssetCopier` 同一套：同内容跳过、不同先 `.bak_eventrotator`），
  **不用 `imageRouter.AddRoute`**（v1.3.12 的教训：会让 SPT 整张图片路由表失效）。
- 尺寸：本机 83 张官方成就图**全部是 98×112 RGBA**；我们的是 256×256 透明底，客户端按 sprite 等比缩放，不影响识别。

## 4. ⚠ 可见性结论（「只在该任务线可用时才显示」到底能不能做）

**不能按活动/条件门控整条显隐。** 反编译 `EFT.Achievements.AchievementTemplate` 的字段表只有：
`Index / Id / ImageUrl / AssetPath / Hidden / ShowConditions / ShowProgressBar / Rewards / Conditions / ShowProgress / Rarity / PlayerSide / Prefab` 等，
**没有任何 visibility / availability 字段**；能「藏整条」的只有 `hidden`：

- `EFT.UI.AchievementsScreen.Show` 过滤条件：`if (!a.Template.Hidden || a.StatusData.UnlockDate != 0)`；
  未解锁的 hidden 成就不会出卡片，只在「隐藏成就」面板累计成 `+N`（`SetupHiddenAchievementsPanel`）。
  ⇒ `hidden: true` 的语义是「解锁前完全不可见」，**不是**「活动没开就藏」。
- 条件级 `visibilityConditions` 只控制**单条目标行**显不显示（`Conditional.UpdateConditionsVisibility`）。
- `showConditions` / `showProgress` / `progressBarEnabled` 只影响卡片内容（目标列表 / 进度数值 / 进度条）。

现取值：`hidden=false`、`showConditions=false`、`showProgress=false`、`progressBarEnabled=false`
⇒ 卡片常驻，但**不会出现「0/128 的怪进度条」**（这是用户点名要避免的那个状态）。

如果以后确实要「活动没启用就整条藏起来」，只有两条路，都要谨慎：
1. 服务端在 Preload 时按当前活动算 `hidden` 写进模板 —— 但 Preload 时活动还没算出来，且要重启才更新；
2. 用 Harmony 包一层 `/client/achievement/list` 按 profile/活动过滤 —— 越权改 SPT 路由，风险大。
**本轮不做**，先把机制结论摆在这。

## 6. 已知缺口（如实）

- **`rewards` 全空**：成就只有荣誉，没有经验/卢布（`gen_achievements.py` 里写死 `"rewards": []`）。
  想加就是改那一行 + 重跑脚本；SPT 侧发奖链路是`ProcessAchievementRewards`（突袭结束比对 profile 增量）/
  `RewardHelper.AddAchievementToProfile`，`Experience` / `Item`(卢布 tpl `5449016a4bdc2d6f028b456f`) 都支持。
- **图标是占位图**（透明底圆环 + 中文名 + "EventRotator"），在深色成就卡片上对比度偏低，建议后续换主题图。
- **`halloween_2023` / `halloween_2022` 没做**：`events.json` 里这两条的 `enableQuests` 都是 `[]`（任务未还原），
  没有任务 id 就没法造条件；`halloween` 用的是官方 17 条里的**前 10 条**（2025 感染者线），
  另 7 条（Dirty Blood / The Root Cause / Matter of Technique / Find the Source / Sample IV / Radical Treatment / Forgotten Oaths）不在条件里。
- **打包**：`tools\ship_er_*.py` 目前只走 `for sub in ("db", "questlines")` ⇒ `achievements\` 和 `images\` 不会进 zip。
- `tools\gen_achievements.py` docstring 提到的 `achievements\README.txt` 目前不存在。
- `_probe_ach\` 里的 `Program.cs` 现在是 Cecil 只读调查探针，不是注入自检 ⇒ `成就注入-说明.md` §5 那条命令
  已不能复现那组数字；注入自检请看 `_probe_ach_verify\`，客户端解析自检看 `_probe_ach_client\`。
